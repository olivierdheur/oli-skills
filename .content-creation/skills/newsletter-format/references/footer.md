# Footer template

The footer goes at the very end of a Substack issue, after `[[SHARE: END]]`. It's built from the user's own details (Step 2 of the skill), never from guesses. Skip any section the user doesn't have. It doesn't count toward the article's word count, and it's left out of X Articles.

## Rules

- **One footer per issue.** On a repeat pass, update it; never append a second one.
- **Verify before pasting.** Every URL loads, and every perk, discount or deadline is still current. Perks expire. If you can't check one, keep it out of the article and flag it in the notes.
- **Referral links need a disclosure line.** Keep the user's wording if they have one.
- **No UTMs on referral, affiliate, booking or social links.** Only the user's own pages get their tracking tags.
- **The name is the link.** One line per entry: linked bold name, colon, what it does for the reader, the perk if there is one. No separate "Try it here" links.
- **Short beats complete.** Around five entries per list. Past that it stops being scannable.
- **Nothing private.** Follow the guardrails in `creator-ikigai.md`.

## Template

Fill in from the user's details, and delete sections that don't apply.

```markdown
***

## Resources

- [**<Offer or product>**](<url>): <what the reader gets, in one line>.
- [**<Free resource>**](<url>): <what it is>.
- [**<Booking or consult link>**](<url>): <what the session covers>.
- **Find me on:** [<Platform>](<url>) · [<Platform>](<url>)

## <Tools I use>

- [**<Tool>**](<referral url>): <what it does for the user>. <Perk, if verified>.
- [**<Tool>**](<referral url>): <what it does for the user>.

*<Disclosure line, for example: Some of these are referral links. I only list tools I use.>*

<Sign-off, if the user has one>
```

## Recurring sections

Some newsletters end with a recurring section (a weekly roundup of jobs, events, reads or opportunities). If the user has one:

- Use their section titles and intro lines word for word. Only the entries change each week.
- Entries come from the user. Never invent a company, event, program, deadline or number to fill a slot.
- Check each entry before it ships: the page is live, the deadline hasn't passed, any figure matches its source. Drop or flag anything that fails. A shorter list beats a wrong one.
- Keep entries factual. No promises about outcomes.
