# Platform notes: formatting for Substack and X Articles

Short on purpose. Platform facts match `newsletter-post/references/platforms.md`, checked against official help docs in November 2026. Platforms change these often.

## What each version keeps

| Element | Substack | X Articles |
|---|---|---|
| Title | Yes: shows in the inbox, app and social cards | Yes: shows on the feed card with the cover image |
| Subtitle | Yes | Only if the user's editor has a place for it; never turn it into body text without asking |
| Body, headings, bold, lists, quotes | Yes, identical wording | Yes, identical wording |
| **Here's what we cover** roadmap | Yes: readers skim in email | Yes |
| Subscribe and share markers | Yes: replaced by native buttons in the editor | No |
| Paywall marker | Only if justified | No |
| Footer | Yes | No |
| Email-only lines ("reply to this email") | Yes | Flag for removal; removing them is the user's call |
| Links to the user's pages | Yes | Yes |
| Images the user supplied | Keep in place | Keep in place; the user picks the cover image |

## Substack

- The first lines double as the email and web preview, so the opening must work on its own. That's the writer's job, but flag it if the formatted top of the article (title, subtitle, first lines) reads poorly in a preview.
- Buttons and the paywall are native blocks. Markers only show where they go.
- Gmail clips emails over about 102KB behind "View entire message". A very long issue with many images can hit this; mention it in the notes if the issue is unusually long.

## X Articles

- Publishing Articles requires a paid X subscription (Premium or Premium+) or a business or organization account. If the user's context doesn't say they have one, ask before preparing an X version.
- The card is the hook: readers see the title and cover image first, mid-scroll, with no inbox. Point out which title option works best as a card.
- Short sections with clear headings travel best. Don't add headings to get there; promote existing sentences only.
- Supported formatting includes headings, bold, italic, strikethrough, lists, images, video, GIFs, embedded posts and links. Skip Substack-only elements: buttons, paywall, footnotes, footer.
- A link back to the user's newsletter at the end is fine if their context allows it. Use their existing words; don't write a new CTA.

## Publishing to both

Format the Substack version first, then derive the X version from it by removing elements, never by rewording. The body stays identical so later revisions stay in sync.
